# Evaluation methodology and limits

SkillStress checks one model response against a person-approved set of candidate rules extracted from a skill. Live results are generated by a language-model judge; they are not deterministic behavior tests.

## Live evaluation

1. Import Markdown. SkillStress heuristically extracts candidate rules.
2. Review and approve the rules in Test.
3. Send the task and skill text to OpenAI or an installed Ollama model. SkillStress does not expose tools or files to the model.
4. Send the response, task, skill text, and approved rules to the same model in a separate judge request.
5. Save the response and each rule result, quote, reason, provider, model, task, duration, and skill snapshot with the run.

The model judges its own response. It may miss a violation, misread a quote, or produce a different result on another run. A score reports that judge's assessment; it does not prove real-world behavior. Independent evaluation, deterministic task-specific validators, repeated trials, and quote verification are future work.

## Repair and comparison

A failed run can request a repair proposal based on the saved skill snapshot, response, and failed judgments. The person can edit and approve the proposal. Approval updates the SkillStress copy; it does not overwrite an imported source file.

The rerun keeps the original task, scenario, provider, model, endpoint, skill ID, and approved rule IDs. History compares results for each rule. The comparison baseline is stored in SQLite and remains available after a backend restart when the same database is used. A changed score is an observed difference; it does not establish that the edit caused the change.

## Mock preflight

The mock path returns synthetic results for a narrow preflight. It makes no model request, executes no tools, and does not validate real agent behavior. It is clearly marked as mock and is not eligible for provider-backed comparisons.

## Limits

- No isolated tool sandbox or application-state execution.
- No deterministic DOM, SQL, or filesystem validators.
- No independent judge, calibration, repeated-trial statistics, or verified evidence quotes.
- No exportable experiment bundle or complete replay guarantee.
- SQLite is local to one backend deployment; it does not synchronize between machines.
